# 产品设计

本文记录 CSV Custom Pro 的产品定位、核心交互、功能规格和产品决策。**每次改用户可见行为，都必须更新本文的功能规格或产品决策记录。**

## 产品定位

CSV Custom Pro 是面向 VS Code / Cursor / Windsurf 的大 CSV 表格编辑器。它的目标不是替代 Excel，而是在代码编辑器里稳定打开、浏览、过滤、编辑几十 MB 级 CSV，并保持键盘优先、低遮挡、可回归测试的体验。

## 核心体验

- 表格化编辑：打开 `.csv/.tsv/.tab/.psv` 后自动显示为可编辑表格。
- 大文件可用：默认允许 100MB 内文件打开，表格行按 chunk 分块渲染，过滤/排序结果也按首屏 + 远程 chunk 返回。
- 列过滤优先：全局搜索对大文件价值低，主流程改为多列组合过滤。
- 低遮挡浮动面板：右下角面板尽量保持单行，超出时横向滚动。
- 可恢复排序：排序按钮三态循环 `A-Z -> Z-A -> 原始顺序`。
- 查找替换：自研 find/replace widget 支持完整文件级匹配、替换和 chunk-aware 定位。

## 右下角过滤面板

```text
过滤: [状态] [全局搜索输入框] [×] [列选择combobox] [包含/等于] [过滤词] [忽略大小写] [忽略空格] [添加] [清空] [chips...] | 行高: [紧凑]
       [全局:"北京" · 2 个列过滤]
       [3. sub_category 包含/忽略大小写: hello] [5. status 等于: active]
```

### 全局搜索

- `#csvGlobalSearch` 输入框位于"过滤:"标签右侧。
- 输入关键词后按 **Enter** 或等待 200ms debounce，自动在**所有列**中搜索子串（忽略大小写），隐藏不匹配行。
- 全局搜索与列过滤是 **AND** 关系：行必须同时满足全局搜索词（任意列包含）和所有列过滤条件才显示。
- `#csvClearFilter`（×）只清空全局搜索，保留列过滤条件。
- 清空全局搜索后，显示所有未被列过滤筛掉的行。
- **与 Ctrl+F 区分**：Ctrl+F 是定位当前文件中匹配位置并高亮（不筛行）；全局搜索是筛行，隐藏不匹配行。
- `filterSortResult` 包含 `globalSearch` 字段，重渲染后输入框不丢值。

### 多列过滤

- 每个条件包含：列、匹配方式、过滤词、是否忽略大小写、是否忽略空格。
- 多个列过滤之间是 `AND`：一行必须同时满足全部条件才保留。
- 每个条件以 chip 展示，点击 chip 上的 `×` 只删除该条件并立即刷新结果。
- `清空` 会删除全部列过滤并刷新。
- 后端仍兼容旧字符串过滤条件，但新 UI 发送对象条件。

### 可搜索列选择

- `#csvColumnFilterColumn` 是可搜索 combobox，不再是原生 `select`。
- 点击后可输入列号或列名片段，例如 `1`、`id`、`na`、`sub`。
- 候选实时更新，显示为 `序号. 列名`。
- `↑/↓` 切换候选，`Enter` 选中，`Esc` 关闭。
- 如果没有匹配，显示 `无匹配列`。
- 候选浮层挂到 `body` 上，用 fixed 定位，避免被单行过滤条的 `overflow-y:hidden` 裁剪。
- 列名 JSON 必须以可直接 `JSON.parse` 的方式写入 `application/json` script，不能用 `&quot;` 之类 HTML entity。

### 匹配选项

- 匹配方式：`包含`、`等于`。
- `忽略大小写` 默认开启。
- `忽略空格` 会删除单元格和值中的所有空白字符后比较，例如 `A B` 可匹配 `AB`。

## 排序

- 表头右侧的排序按钮触发排序，点击表头文字本身不排序。
- 三态循环：未排序 -> 升序 -> 降序 -> 原始顺序。
- 后端第一次排序前保存 `sortSnapshotText`；非排序编辑会清空快照。

## 行高

- 右下角行高按钮在 `紧凑` 与 `自然折行` 间切换。
- 紧凑模式会把换行显示成可见标记并保持单行高度。
- 用户仍可拖动行底边手动调行高，尺寸会持久化。

## 查找替换

- `Ctrl/Cmd+F` 打开查找，`Ctrl/Cmd+H` 打开替换。
- 支持大小写、全词、正则、保留大小写替换。
- 匹配由扩展侧按全量数据计算，前端按坐标定位并在需要时触发 chunk 加载。

## 改代码时怎么更新本文

- 改 UI/交互：更新对应功能规格，并在“产品决策记录”加一行。
- 改默认配置：记录默认值变化和原因。
- 改大文件策略：记录性能目标和必测场景。
- 只改内部重构且行为不变：可以不加产品决策，但如果影响模块命名或调试入口，应更新 `技术架构-architecture.md`。
